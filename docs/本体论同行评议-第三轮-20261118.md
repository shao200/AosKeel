## 一、系统摘要（评审者复述）

AosKeel 是"基于本体的 Agent 系统"的规格驱动脚手架：领域以九类 YAML 声明（ObjectType / Property / LinkType / ActionType / ContextType / AggregateType / Invariant / Mapping / ProcessType）写入 `spec/`，经五步注册管线编译为结构检查与受限布尔条件，权威事实是仅追加的事件日志（八字段：event_id / stream_id / expected_version / event_type / payload(含 valid_time) / transaction_time / action_id / principal，`src/kernel/store.py:26-34`），对象状态是事件流的只读投影（`src/kernel/projection.py:30-47`）。核心卖点是"可治理本体"：ActionType 把许可、条件、副作用、审计声明为可执行契约，能力清单不完备则内核不启动（INV-13 / GOV 启动前置）。项目自我划界明确：不是 DL 推理机、不是规划器、不是 RDF/SPARQL 三元组库。

## 二、理论评判

### 2.1 本体定义的学术锚定：实质达标，引用链有断层

项目对"本体"的工作定义（`docs/guide/01-foundations.md:7`「对特定领域中概念、关系、属性与规则所做的显式、形式化结构化定义」）与 Gruber (1993)「概念化的显式规范」、Studer 等 (1998)「形式化、显式规范、共享」的合取口径一致，且四谱系定位表（描述逻辑 / 动作形式化 / 道义逻辑 / 工业图本体，README §1 与 01-foundations）经前轮修订后已把 Palantir 降为工程形态对照、把 PDDL 更正为 McDermott et al. (1998)——这是教科书级的谱系自我认知。

**遗留问题**：经典定义（Gruber / Studer / Guarino）目前只出现在被收进仓库的前轮评议文本里，正典与九分册指南正文对其零引用（`08-enterprise-app-guide.md:45` 甚至无出处地使用 Gruber 措辞）。一份以"ontology-based"为理论宣称的规范，其术语学奠基应落在正典附录 D 而非依赖第三方评议转述。Guarino 意义上的"本体 vs 轻量本体 vs 数据模型"分层讨论完全缺位——这恰是本项目最需要自卫的位置，因为它的产物按 Guarino 分类学更接近"带公理化约束的数据模型 + 动作理论"，而非"本体"。项目用"治理性本体"这个自造词回应了这一点，但自造词需要锚定在既有文献上才构成理论增量。

### 2.2 从描述本体到"可治理本体"：增量真实，机制归位准确

`06-formal-semantics.md:236-251` 的 OWL↔AOS 翻译限制表是全项目理论质量最高的一节：它逐行承认 ObjectProperty→LinkType 受限、RDF 三元组不可直接翻译、ActionType / 会话流 / 创世窗口"不可"翻译，理由是"OWL 描述什么为真，无法表达谁能如何改变世界"。这个划界是诚实且正确的——把"许可"处理为启动期门禁而非推理结论（README:35「startup-time gate, not an inferred conclusion」），其形式化归宿是道义逻辑与授权语义，项目自己也这么指认。

开放/封闭世界的处理同样成熟：不选边，改口径为三层（`06-formal-semantics.md:89-95`）——变更通道封闭（AX-1/INV-1）、投影状态确定（KS-3.4/P-16）、外部现实开放但带出处——并明说"这不是标准 OWA，也不是朴素 CWA"，代价表（:119-129）逐格交代了可判定性、性能、审计体积。这比多数自称"本体"的工程项目对 OWA/CWA 的处理要严谨。

### 2.3 事件本体论：工程上自洽，哲学上有一块该接而未接的地基

"个体是事件流的投影"（AX-1，`aos-spec.md:79`；T05/T17）在事件溯源传统内完全自洽，同一性问题走 P-8（锚点不可删除、`same_as` 零语义、归并史可重放），双时态走 P-13/INV-8。但全库检索无 endurant / perdurant / 延续体 / 接续体 / 四维主义任何字样：本项目实际上采纳了一个**接续体（perdurantist）立场**——个体即时间上的投影切片、状态是 valid_time 上的函数——却没有认领这个哲学传统。这不是苛求：接上 `4D fluents` 与事件演算的既有文献，能把"个体是什么"从工程约定升格为有出处的本体论承诺，正好补强 2.1 指出的引用链断层。

### 2.4 条件语言与不变量：有语法制约，无模型论

KS-3.2 的 R1–R11 profile（`aos-spec.md:132-152`）给出了清晰的语法侧边界：纯集合操作、显式快照输入、禁 I/O 与时钟、集合规模上限 10⁵、R10 布尔档、R11 映射档禁判断分派。实现侧（`src/interpreter/boolean_profile.py`，75 行）用 AST 白名单 + 受限 builtins 的 `eval(compile(...))` 兑现，且 docstring 自承"纯性不可证明、只能被实现与核对"。问题在理论层：

1. **无模型论**。文中宣称"求值终止性可证"（`06-formal-semantics.md:123`），但仓库内没有任何语义定义或证明草稿。对一个把"编译进机器检查"作为核心卖点的框架，至少应给出求值环境的抽象语义，否则"可证"只是宣称。
2. **表达力边界靠不可表达性兜底，方向正确但论证单薄**。"重放时做判断在结构上不可表达"（`03-implementation.md:152-154`、`02-architecture.md:187-189`）是漂亮的可靠性设计，但目前只有一处展开，值得成为正典级论点。

### 2.5 能力问题机制：前轮缺位已补，但规范条文缺位仍在

十条 CQ（当前状态 / 谁能批准 / 金额门槛 / 审计依据 / 跨系统同一性 / 跨聚合联动 / 唯一写者 / 投影重建 / Agent 所见 / 规范变更感知）已从教学条目升格为可执行声明：`spec/competence/CQ-1..10.cq.yaml`（question/answerer/probe/expect/evidence 五槽）+ `tools/cq.py` 回答者注册表 + `aos cq` 在真实内核上跑，删题/未注册/断言错即 fail-closed。CQ-9、CQ-10 超出经典本体工程清单也被自我指认（`06-formal-semantics.md:164`），"证明给定域可复现、不等于任意域完备"的边界声明（:168）到位。**但 `aos-spec.md` 全文无 CQ 条款**——能力问题停留在信息性指南 + 声明层，未进入正典。对一份自称"规范驱动"的文件集，这是一个可修复的地位错配。

### 2.6 治理即启动条件 + 不可声明化残余：理论贡献的主体

GOV-1 两级社会契约（算术由平台强制、正当性由社会担保，`aos-spec.md:373`；KS-8.3 :197），配合 §9.3 只承认三项不可声明化残余（能力集裁定、创制任命、外部观测历史重建），构成全文最大的一块真理论增量：**把"合法性从哪来"作为形式系统的显式外部项列出，而不是假装它能被系统内生**。"模式的合法性来自它防止的事故，不来自设计品味"（`02-architecture.md:113`）的反事实设计法同样可辩护。这套东西目前散落在正典条款与指南里，没有一篇独立的理论章把它与 deontic logic / institutions（社会本体论，Searle 传统）对接——这是"major revision → minor revision"路径上最值得做的一件事。

## 四、总体评判与结论

**理论侧**。对"ontology-based"这个宣称，本项目交出的不是推理能力，而是一个更稀缺的东西：一份把**治理显式形式化为启动条件、并把不可形式化的合法性残余逐条列出**的本体工程规范。OWL↔AOS 不可译表、三层开闭世界口径、CQ 可执行化、反事实设计法，都站在既有文献的正确一侧。主要理论欠账是三处引用链断层：经典本体定义未入正典、接续体立场未认领、治理理论未与道义逻辑/制度事实文献对接；外加条件语言缺模型论。

**实践侧**。前轮全部 P0/P1 裂缝经独立复核确认已修，修复方式（物化投影、内核证据、注册期拒绝）与承诺一致而非表面应付；测试与门禁是真实判据。本轮发现一条同族 P1 漏网（Invariant 表达式无消费者）和一组 P2 声明-执行裂缝（dry_run、contexts 强制、双射强度），均属"编译了但没人读"的同一根因——建议在注册管线加一条通用规则：**每个声明字段 MUST 有命名消费者或注册期显式豁免**。

**审稿结论**：
- 作为可验证的本体工程脚手架：**accept（强）**。
- 作为"ontology-based"的理论宣称：前轮 **major revision** 的六条要求五条已闭环，本轮降级为 **minor revision**——通过条件收敛为三件事：①修复或明确划界 Invariant 执行点（P1）；②把经典本体定义与行动形式化/道义逻辑文献引入正典附录（含接续体立场的显式认领）；③给条件语言补一份最小求值语义（模型论），使"终止性可证"从宣称变为可核对的命题。

完成这三条后，"治理即启动条件 + 合法性残余清单"有潜力成为 Agent 规格领域被引用的参考框架。
