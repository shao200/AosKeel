# 第 1 部分 · 基础

## 1. 文档约定、规范性语言与编码规则

规范性关键词按 RFC 2119 解释：MUST / MUST NOT（绝对要求，违反即不符合本规范，强制点见第 8 节）、SHOULD / SHOULD NOT（偏离须书面理由并经 GOV-5 处置）、MAY（真正可选）。

条款编号前缀：AX（公理）、KS（内核语义）、P（模式）、INV（全局不变量）、BOOT（启动）、GOV（治理）、VER（验证）。INV 为最高裁决——任何条款、模式、实现、SpecChange 与之冲突时以 INV 为准。VER 是 MUST 义务的可执行强制点清单，按 GOV-3 修订，禁止绕过。术语一律以 1.1 为准，变体禁入规范性条款。

1.2 编码规则（v2.0 起，文档工程规则，非本体语义条款）：

- 法则型规范性内容（公理、条款、模式）以散文条款块存储；
- 登记型规范性内容（术语、矩阵、清单、登记表）以代码块清单存储；
- 表格不承载 MUST——表格仅承担导航与摘要；未来任何节若以表格承载规范性内容，MUST 双编码（GOV-2.4）；
- 违反本规则不构成语义违规，但构成签发门结构层失败。

### 1.1 术语表（×26）


# 第 2 部分 · 核心公理

## 2. 核心公理

全部条款由以下五条公理派生。任何实现选择与公理冲突时以公理为准；任何条款间张力以第 5 节 INV 裁决。

**AX-1 事件即真源，行动即变更。** 对象的状态是事件流的投影；改变状态的唯一途径是经 ActionType 评估后向本体事件日志追加事件。本体权威状态在 Action 下封闭；外部现实只作为观测进入——观测经由声明的摄取 Action、携带出处，永不作为静默写入。

**AX-2 概率性提议，确定性断言。** 概率性机制只能产生提议；对世界的任何变更必须由确定性 Action 在治理边界内完成。

**AX-3 三分离。** 类型/实例、声明/实现、平台契约/上下文边界必须全程保持。

**AX-4 闭环可审计。** "Agent 当时基于什么信息、发起了什么行动、结果如何"必须事后可重放。

*（范围注：可重放的完整性受 P-17 擦除降级约束——密钥销毁后重放降级为哈希承诺验证。）*

**AX-5 Schema 即数据。** 元 Schema 自身是四元组实例，可被治理、可被审计、可被 Action 变更；治理流程是第一个工作流。

# 第 3 部分 · 内核语义

## 3. 内核语义（KS ×30）

### 3.1 事件即真源

**KS-1.1** 本体事件日志 MUST 是唯一权威状态来源，物理形态 append-only。

**KS-1.2** 每条事件 MUST 携带：event_id（平台生成，单调）、stream_id、expected_version、event_type（含 Schema 版本号）、payload（含 valid time）、transaction_time、action_id、principal。

**KS-1.3** 事务边界 MUST 等于单条事件追加的原子性边界；状态转移不变量 MUST 在追加之前求值，决定是否允许追加。

**KS-1.4** 版本冲突 MUST 触发完整重求值（结构 → 条件 → 聚合不变量）；禁止仅重试追加而不重求值。

### 3.2 双事件流与决策流

**KS-2.1** 本体事件日志与会话事件流 MUST 物理与逻辑分离。

**KS-2.2** 会话事件流 MUST 是只增观测记录——不构成本体状态、不参与任何投影的权威重建、不由 ActionType 写入。

**KS-2.3** 会话流追加为内核中介的通道写入，MUST 在能力清单中单列，每条强制主体归属。

**KS-2.4** 不变量 Function 与 Submission Criteria 的求值闭包禁止读取会话事件流。

*（释义：禁令作用于内容解引用——决策事件的双引用字段属本体元数据，闭包可读；会话内容经会话通道解引用，闭包不可达。）*

**KS-2.5** 每条决策事件 MUST 含双引用：（投影标识，transaction_time）与（会话事件引用）。投影半边是权威事实，会话半边是推理证据，两者永不互替。

**KS-2.6** 决策事件 MUST 归属本体事件日志的决策流，经内置 ActionType RecordDecision 追加（INV-13 能力清单列名）；决策事件 MUST NOT 经域聚合不变量门控——其求值管线为 SC 结构校验（投影引用存在性、transaction_time 合法性）+ 主体归属强制。

### 3.3 Function 受限演算

**KS-3.1** Function 按运行时分为宿主语言与受限解释器两类；解释器内含布尔型与映射型两个输出 profile。纯度封闭律：

- 受限域对宿主域封闭——受限 Function（任一 profile）禁止调用宿主 Function；
- 宿主 Function 禁止进入重放路径（KS-3.4）；
- 受限域内部——布尔型 MAY 调用映射型；映射型 MUST NOT 调用布尔型；
- R6、R8 对调用树整体适用，不限于顶层函数。

**KS-3.2** 受限解释器 MUST 强制以下求值规则：

```
R1  允许：聚合内属性读取
R2  允许：显式声明的快照输入（声明式枚举，每次求值捕获一次）
R3  允许：纯集合操作
R4  禁止：任何 I/O 原语
R5  禁止：系统时钟读取；"现在"只能从求值上下文读取（valid_time / transaction_time）
R6  禁止：无界递归与循环（解释器强制深度/迭代上限；作用于调用树整体）
R7  禁止：修改任何聚合状态
R8  集合操作规模上限：由 AggregateType 求值预算声明，缺省 10^5 元素
    释义：注册期——预算声明 MUST ≤ 本条上限，超限注册拒绝；
          运行时——门控求值超限 → fail-closed（追加被拒）；
                   探测器路径超限 → 产生预算超限类违规对象（经 RaiseInvariantViolation）；
                   禁止静默降级。
R9  命名空间隔离：不变量 Function 与一般 Function 不同命名空间
R10 布尔型 profile：结果只允许 true / false
R11 映射型 profile：允许数据整形，禁止布尔判断路径
    释义：映射型 MAY 依结构分派（Schema 版本、字段存在性、空值、字面量等值）；
          MUST NOT 依判断分派（语义谓词）——判断只出现在求值顶层，永不嵌入变换内部。
```

**KS-3.3** 受限解释器版本 MUST 进入求值审计记录，并出现在内核能力清单上。

**KS-3.4** 重放路径（upcasting、投影重建）只允许受限解释器的映射型 Function。

### 3.4 权威状态封闭与观测摄入

**KS-4.1** 外部数据源进入本体 MUST 二选一显式声明：

- 封装为 Action：外部变更触发摄取 ActionType，事件负载含出处（来源系统、源时间、置信度）；
- 只读投影：本体对外部源只读，经 Mapping 投影进上下文，不产生本体事件。

**KS-4.2** 禁止存在直接写本体事件的第三条路径。

### 3.5 Schema 演化契约

**KS-5.1** 事件负载 MUST 带 Schema 版本号；旧事件永久保留。

**KS-5.2** 字段变更通过 upcasting 处理（读取时转换旧事件）；upcasting 声明 MUST 是 Schema 治理提案的强制附件。

**KS-5.3** upcasting MUST 通过 golden test（新读旧事件 = 历史快照），注册期强制。

**KS-5.4** 禁止删除事件类型；废弃声明保留读取路径。

### 3.6 valid time 取值域

**KS-6.1** valid_time MUST ∈ (−∞, transaction_time]；禁止未来 valid time。

**KS-6.2** 预约与预约式生效 MUST 建模为当前状态加调度效果（P-9 或探测器）。

**KS-6.3** 补录事件 MUST 携带出处并触发投影重建标记；补录不重跑历史门控判定，仅更新当前投影并触发受影响时间限定不变量的重探测。

### 3.7 Submission Criteria 子语言

**KS-7.1** Submission Criteria MUST 由两部分构成，注册期编译：结构校验（声明式子语言：类型、必填、基数、引用存在性，不进解释器）+ 条件校验（受限布尔 Function）。

**KS-7.2** 追加前求值管线 MUST 固定为：结构 → 条件 → 聚合不变量 → 追加。

### 3.8 创世窗口

**KS-8.1** 审计日志第一条（创制任命）授权一次性创世写入能力 GenesisWrite。

**KS-8.2** GenesisWrite 的 Submission Criteria MUST 为声明式谓词"治理工作流尚未闭环"；首个完整治理周期完成之刻，该谓词永久为假，能力自动熄灭（创世熄灭）。

**KS-8.3** 创世批次（治理上下文、BOOT-2/3 验收所需元对象、steward 记录）的合法性来自创制任命，不来自流程合规。

**KS-8.4** "完整治理周期"定义为 GOV-5 第 1–5 步全部完成且处置为签发。

**KS-8.5** 创世窗口 MUST 在创制任命记录中声明 TTL；到期未完成的，进入创世冻结——GenesisWrite 冻结，再启用 MUST 由创制任命主体再授权并记为新审计事件；周期完成后进入创世熄灭——不可逆，内核禁止存在任何重启用路径，再授权凭据对此无效。窗口开闭时间戳 MUST 记入审计。

# 第 4 部分 · 模式目录

## 4. 设计模式（P ×17）

开放集声明：本目录是开放集，新模式准入见 GOV-4。每模式"移除后果"为强制项——新模式提案 MUST 引用其预防的事故类别（附录 B.2）。纯度封闭律（KS-3.1）适用于所有模式声明的求值过程。

**P-1 声明式 Action（移除后果：A）**

- 意图：将"世界能被怎样改变"提升为可枚举、可授权、可审计的一等结构。
- 结构：ActionType 声明参数、Submission Criteria、权限、副作用、审计要求；事务边界 = 事件追加的原子性边界；状态转移不变量在追加前求值。
- 约束：一 Action 一聚合 = 事件追加原子化；跨聚合 MUST 降级为 P-9 补偿，禁止分布式事务。

**P-2 Aggregate 一致性边界（移除后果：B）**

- 意图：为不变量求值提供事务边界，为并发控制提供加锁单位。
- 结构：AggregateType 声明一致性单元；乐观锁 = 追加事件时校验预期流版本；不变量求值闭包封死在聚合内 + 显式声明的快照输入；MUST 声明求值预算。
- 约束：引用闭包外的活数据禁止；求值预算超限路径按 R8 释义——注册期拒绝，运行时 fail-closed 或违规对象，禁止静默降级。

**P-3 Bounded Context（移除后果：C）**

- 意图：限定语义边界，解决多义性，本地化本体政治学。
- 结构：ContextType 声明命名空间 + 统一语言 + 所有权（steward）+ 延迟预算；全局本体收缩为最小共享内核。
- 约束：全局身份是稀缺品；上下文边界可有意识顺势组织架构，禁止无意识漂移。

**P-4 结构性链接（移除后果：D）**

- 意图：用一般约束组合出"零语义链接"，避免内核开洞。
- 结构：LinkPattern 元声明 + 三项强制校验——属性集为空、遍历透明标记存在、无 ActionType 绑定写入。注册期自动校验，违反即拒绝声明。
- 约束：模式 MUST 以元 Schema 声明，禁止以注释或约定存在；同一组合 MUST 可服务其他领域（出处、审计关联）；启动早期（BOOT-2/3）以受控实例化标记为启动内建，BOOT-4 后开放业务上下文。

**P-5 声明式 Mapping（移除后果：E）**

- 意图：将防腐层从代码升格为可审计的语义契约。
- 结构：Mapping 声明源概念在目标上下文被解释为什么、哪些属性被投影/丢弃/转换；转换逻辑 MUST 是受限映射型 Function；经锚点解析。
- 约束：MUST 声明语义损耗；MUST 有 Golden Set 测试。

**P-6 不变量三元组（移除后果：F）**

- 意图：让"不变量即传感器"落地——没有响应协议的传感器只生产警报疲劳。
- 结构：不变量 = 声明（不变量 Function，KS-3）+ 违规语义（写时阻断 / 异步检出进入隔离态）+ 修复绑定。
- 约束：MUST 支持时间限定——违规是对时间的判断；修复绑定 MUST 纳入 ActionType 废弃检查的强制依赖项；状态转移不变量由 KS-1.3 门控；时间限定不变量由探测器在投影上求值，违规对象经内置 RaiseInvariantViolation 写入（INV-13）。

**P-7 违规即对象（移除后果：G）**

- 意图：让违规成为可治理、可追踪、可被 Agent 消费的一等实体。
- 结构：InvariantViolation 为 ObjectType；生命周期 = 检测 → 分类 → 提案 → 修复 → 关闭；LinkType 指向不变量声明、受影响对象、修复 Action。直系祖先为 SHACL 验证报告结构。
- 约束：修复提案的 SC MUST 结构性绑定违规对象本身，禁止引用式关联；写时阻断与异步检出是同一生命周期的两个入口，后续修复流程统一。

**P-8 Identity Context（移除后果：H）**

- 意图：把身份治理收纳进统一模型。
- 结构：Identity Context 是特例 Context；锚点是不可删除 ObjectType，只可归并或废弃；same_as 是结构性链接；归并是平台内置确定性 Action；匹配引擎产出候选对与置信度（一般 Function），归并确认是治理 ActionType。
- 约束：锚点属性双时态强制；归并历史 MUST 可重放；跨上下文只有 same_as 一种合法链接，零语义、不授予权限；BOOT-2 受限实例化，BOOT-3 完整实例化。

**P-9 ProcessType 跨聚合流程（移除后果：I）**

- 意图：为跨聚合流程提供声明式出口，防止聚合退化。
- 结构：声明式 Saga 载体；补偿 = 追加补偿事件；每个补偿本身是 Action。
- 约束：每个补偿 MUST 可审计、可重试、可幂等。

**P-10 Agent 居住地（移除后果：J）**

- 意图：将 Agent 定位为"居住在特定上下文、受该上下文约束的行动者"。
- 结构：Agent 权限 = 角色 × 所在上下文；能力面 = 全局能力 ∩ 上下文可用 Action 集。
- 约束：Agent MUST 是 Action 的调用入口，禁止是 Action 的绕过路径；上下文跳转权限不继承。

**P-11 Schema 即数据（移除后果：K）**

- 意图：让元层自举。
- 结构：ContextType 的实例是 Context 对象、AggregateType 的声明是 Aggregate 对象；平台内置治理不变量 + 治理 Action（ProposeSchemaChange / ApproveSchemaChange / DeprecateSchemaObject）。
- 约束：治理流程 MUST 用四构造建模；启动早期（BOOT-2 起）标记为"启动内建能力"，由 GenesisWrite 实例化，不计入业务模式集。

**P-12 Dry-Run（移除后果：L）**

- 意图：让人审的对象从"Agent 说了什么"升级为"这一步会把世界改成什么样"。
- 结构：平台模拟 Action 在假想世界状态上的下游影响；Schema 变更同样支持模拟违规面。
- 约束：MUST 与真实求值使用同一不变量求值器；默认作用域 = 聚合闭包 + K 跳链接，超限显式扩域并留痕；MUST 报告未遍及的链接，禁止静默忽略；MUST 绑定进治理 Action 的 Submission Criteria——批准时点重校验。

**P-13 双时态记录（移除后果：M）**

- 意图：让"Agent 当时基于什么事实"成为可精确回答的问题。
- 结构：所有承载决策依据的属性携带 valid time 与 transaction time；transaction time 即事件日志位置，valid time 进事件负载。
- 约束：transaction time 由平台维护，禁止向前写入；取值域按 KS-6.1。

**P-14 存量合规（移除后果：N）**

- 意图：让声明式不变量在生效时对过去有个说法。
- 结构：Schema 变更 MUST 声明迁移路径——数据修复 Action 流程，或仅对新写入生效的宽松版本；事件维度按 KS-5。
- 约束：迁移窗口 MUST 显式、有时间边界、被 P-9 编排。

**P-15 基座与破窗（移除后果：O）**

- 意图：让"不可修改的宪法"具备真实执行力。
- 结构：基座三层执行——不可能（内核中不存在任何能触达的 ActionType / API / 运维例程）、响亮而有界（破窗作为平台 Action 类：限时、自动过期、双重记录、强制触发事后评审 Process）、只增不改（审计不可变性精确作用于历史记录）。
- 约束：基座准入标准 = "没有它闭环即失效"。基座仅三项：审计只增、周界完整、破窗响亮。其余规则刚性（更高法定人数、冷却期、强制 Dry-Run）用分级机制表达，属治理光谱而非基座。

**P-16 投影与决策输入（移除后果：P）**

- 意图：为读侧声明物化策略，将"Agent 当时看到什么"作为审计闭环的读半边。
- 结构：投影声明物化策略与延迟预算；Agent 决策输入的记录形式是（投影标识，transaction_time）双引用。
- 约束：投影 MUST 可重建——从本体事件日志全量重放；投影禁止做权威状态判断；延迟预算写进 ContextType 声明。

**P-17 可验证遗忘（移除后果：Q）**

- 意图：调和审计只增与遗忘权——遗忘被记录但被遗忘者不可读。
- 结构：PII 按主体加密存储；擦除 = 销毁主体密钥（EraseSubject 是治理 Action）；密钥销毁产生"密钥已销毁"事件；审计哈希仍可验证，事件结构仍在，只是不可读。
- 约束：擦除 MUST 经由 Action；销毁动作双记录；擦除后重放降级为哈希承诺验证——可验证不可读，不承诺重建被擦除内容；该降级为有意调和，非缺陷；要求销毁事件结构本身的合规域超出适用范围（第 9 节）。

## 6. 启动序列（BOOT ×5）

启动顺序本身即构造能力的验收测试。元 Schema 按验收需求增长，不按预见增长。

**BOOT-0** 内核部署 + 能力清单发布（系统外行为）。能力清单 MUST 枚举完备、版本化，禁止遗漏（含会话流通道写入与 RecordDecision）。同时激活规范工件哈希登记（附录 E）。

**BOOT-1** 创制任命，MUST 记为审计日志第一条；MUST 声明创世窗口 TTL（KS-8.5）。

**BOOT-2** 治理流程实例化（第一个工作流）。启动内建能力以 GenesisWrite 实例化：P-11 治理对象全量、P-4 结构性链接能力（受控）、P-8 Identity Context（受限）。验收：Proposal→Approval→生效 MUST 全部用四构造建模；创世窗口闭合时间戳 MUST 在案。

**BOOT-4+** 业务上下文按需引入。

## 7. 治理与 SpecChange（GOV ×6）

**GOV-1** 两级社会契约：算术（平台强制校验：法定人数、冷却期、审批链路结构）；正当性（社会担保，非平台保证：steward 资格、创制任命本身）。

**GOV-2** 工件同一性与内容寻址

- **GOV-2.1** 本规范分发 MUST 携带工件标识（附录 E 登记）；一切 SpecChange 提案、评审与处置 MUST 视为针对该标识的可检验断言。
- **GOV-2.2** 任何针对规范工件内容的断言（存在性、缺失、矛盾、截断）MUST 引用其所依据的工件标识（哈希或指纹清单条目）；无引用的工件级断言，在 GOV-5 第 2 步降级为疑询并退回补充，不得作为拒签依据。设计级主张不受此限，但 MUST 以条款编号定位。
- **GOV-2.3** 工件哈希为分离式——覆盖冻结正文全文（登记条目自身除外），登记于审计日志与分发清单；文档内禁止内联哈希。自指哈希不可构造，寻址必须外置。
- **GOV-2.4** 签发包 MUST 附条款指纹清单（附录 F），逐节核对"条数 + 首条锚 + 末条锚"。验证两层：结构层（任何介质可执行）、密码学层（BOOT-0 激活）。编码规则：登记型规范性内容 MUST 以清单/代码块编码存储，表格不承载 MUST（1.2）；若任何节以表格承载规范性内容，MUST 双编码，两者同入哈希域。v2.0 起正文以条款块原生存储，双编码义务由结构满足。
- **GOV-2.5** 结构层核对失败时，失败报告 MUST 指明失败节与失败形态。分歧二分：工件缺陷（正典缺内容）→ 按 GOV-6 记录并修订文本；传输缺陷（正典完整、副本退化）→ 处置 = 重新分发，禁止为传输缺陷修订冻结文本。传输分歧记为事故类别 R。

# 第 6 部分 · 边界

## 9. 适用边界与不可声明化残余

9.1 适用范围（信息性）：AOS 适用于错误代价远大于建模成本的领域——金融敞口、临床试验、合约审批、国防决策、关键基础设施。小团队场景下过度工程风险高。

9.2 显式不适用（采用前 MUST 声明）：合规要求销毁事件结构本身（而非仅销毁可读性）——审计只增与该要求不可调和；决策者拒绝承担建模投资，要求开箱即用；无法指定 steward 的领域。

9.3 不可声明化残余（仅三项，均为世界中的事件，系统记录而不执行）：内核能力集的裁定（BOOT-0，系统外行为）；创制任命（BOOT-1，审计日志第一条）；经 KS-4.1 路径二进入的观测，其历史重建依赖外部系统自身的可审计性——AOS 只保证本体半边的重放。

## 附录 R：理论谱系与立场（信息性）

本附录不产生 MUST 义务，仅交代 AOS 与既有理论的关系并显式认领接续体立场。条款冲突时
以正文条款与 INV 裁决，本附录不得作为推翻条款的凭据。

### R.1 经典本体定义

Gruber（1993）将本体界定为"概念化的显式规格"（an explicit specification of a
conceptualization）；1995 年补入"形式化"（formal）与"共享"（shared）两项限定。AOS 位于
该定义线内：`spec/` 的九类声明是对领域概念化的显式、形式化、可共享规格。AOS 的增量不在
描述世界，而在把治理义务写成启动条件。术语 T01（四元组）与 AX-1 沿用上述定义，未另立新义。

### R.2 接续体立场（显式认领）

AOS 接续的是"本体作为契约"的工程传统，**不接续描述逻辑的开放世界自动推理传统**。
附录 D 的 OWL↔AOS 不可译表划定该边界：AOS 不宣称 OWL 推理机能力，亦不以 OWL 语义替代
INV 裁决。姿态为"站在其上，非平行"——借用本体的显式规格纪律，同时把不可形式化的合法性
残余逐条列出（第 9.3 节），而非宣称其可计算。

### R.3 行动形式化

事件即真源（AX-1 / KS-1）与读时升级（KS-5）处于 Situation Calculus 与 Event Calculus
的行动形式化谱系：行动导致状态迁移，历史不可改写，查询相对于历史求值。AOS 的增量在
"追加前求值"（KS-1.3）与"冲突完整重求值"（KS-1.4）——二者把行动的形式语义接到可执行的
提交门上，使"行动"不仅是被建模对象，也是被门禁裁决的对象。

### R.4 道义逻辑与制度事实

权限表达（`Agent 权限 = 角色 × 所在上下文`，INV-4 / P-10）可对照 von Wright 的道义逻辑与
Jones–Sergot 的规范位置（normative position）语义；治理两分（GOV-1：算术强制 / 正当性
社会担保）可对照 Searle 的制度事实与构成性规则（constitutive rules）——"创制任命"之所以
成为事实，依赖集体承认而非平台计算。AOS 将这条边界写成 GOV-1 与第 9.3 节的残余清单，
不把社会担保伪装成机器判定。

### R.5 理论欠账披露

上述对接均为谱系定位，**不构成"已形式化归约"的宣称**：道义算子尚未映射为 AOS 的一阶编码；
制度事实仅以残余清单方式登记，未给出构成性规则的推理演算。此为本版明确的理论欠账，
供后续 GOV-3 提案逐条收敛，不得以本附录充作已闭合的证据。

## 附录 S：条件语言最小求值语义（信息性）

本附录为信息性说明：对 KS-3.3（Function 受限演算）与 KS-7.1（SC 两段式 / 受限布尔档）
已含的约束给出可核对的形式定义，**不新增 MUST 义务**。实现与本附录的差异按 KS-3.3 /
KS-7.1 与 INV-11 裁决，不得反向援引本附录改写条款。

### S.1 语法（受限布尔档）

```
Atom   ::= snapshot.<path> <op> <literal>
         | principal.contexts CONTAINS <context-id>
         | principal.roles CONTAINS <role-id>
op     ::= = | != | < | <= | > | >=
Expr   ::= Atom | not Expr | Expr and Expr | Expr or Expr | ( Expr )
```

`<path>` 为权威快照的字段点分路径；`<literal>` 为字符串、数值或布尔字面量。语法不含
函数调用、变量绑定、递归定义、循环构造与宿主语言求值——这是 S.4 终止性的语法前提。

### S.2 求值环境

```
env = (snapshot, principal, now)
```

- `snapshot`：权威状态封闭后的只读快照（KS-3.4 / P-16）；
- `principal`：提交者身份、出示角色与所在上下文（INV-4 / P-10）；
- `now`：提交时点，取值域按 KS-6（valid time）约束。

求值函数 `eval(expr, env) → Bool` 为全函数：字段缺失、类型不合或上下文缺席时返回
`false`，不得抛宿主异常，不得产生副作用（KS-3.1 纯度封闭律）。

### S.3 求值规则（结构归纳）

```
eval(snapshot.p op v, env) = x 缺失 → false；否则比较 x 与 v 是否满足 op
eval(principal.contexts CONTAINS c, env) = c ∈ principal.contexts
eval(principal.roles    CONTAINS r, env) = r ∈ principal.roles
eval(not e,       env) = ¬eval(e, env)
eval(e1 and e2,   env) = eval(e1, env) ∧ eval(e2, env)      // 短路
eval(e1 or  e2,   env) = eval(e1, env) ∨ eval(e2, env)      // 短路
```

### S.4 终止性命题（可核对）

**命题**：对任意良构 `Expr e` 与任意 `env`，`eval(e, env)` 在有限步内停机，且步数
`≤ |nodes(e)|`（AST 节点数）。

**证明**：按 `Expr` 结构归纳。`Atom` 为常数步，步数为 1；`not e` 的步数为
`1 + steps(e)`；`and` / `or` 因短路取值，步数 `≤ 1 + max(steps(e1), steps(e2))`。
由归纳假设 `steps(sub) ≤ |nodes(sub)|`，合取得 `steps(e) ≤ |nodes(e)|`。S.1 的语法无递归、
循环、函数调用与宿主求值，故不存在非终止归约路径。证毕。

该命题可由 AST 节点计数与解释器中止性测试核对，使"终止性可证"从宣称变为可检验断言；
它约束的是语法封闭性，不替代 VER-1..33 的任何强制点。

### S.5 与模板边界的关系

模板层的 SC 编译器（`src/kernel/sc_compiler.py`）实现 S.1 的语法编译与 `dry_run ⇒ audit`
蕴含检查；受限解释器按 S.2–S.3 求值；S.4 的终止性由受限语法保证。Invariant 声明的
`declaration.expression` 与受限布尔档同源，但其运行时检测器为**实例侧义务**，并以
`config/verification.yaml` 的 `invariants: {gate: false}` 为机器标记（见两版 README §9）。
本附录不改变该边界，亦不把 Invariant 表达式升格为已接线的运行时约束。
