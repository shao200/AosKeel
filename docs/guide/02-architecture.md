# 02 · 体系逻辑与架构模型

> 信息性文档，不产生规范条款。条款编号与效力以 [aos-spec.md](../aos-spec.md) 为准；本指南的"三层 + 治理层"是对条款的**归纳视图**，不是新增规范层次。

## 结论先行

AOS 的体系逻辑是一条**七段推导链**：

```
AX 五条公理 → KS 内核语义(30) → P 模式(17) → INV 全局不变量(13，最高裁决)
    → BOOT 启动序列(5) → GOV 治理(6) → VER 验证矩阵(33，强制点)
```

三条效力规则：① 任何实现选择与公理冲突，**以公理为准**；② 条款间张力，**以 INV 裁决**；③ VER 是 MUST 义务的可执行强制点，禁止绕过。

架构模型可归纳为**三层数据 + 一层横切治理**：

```
                    ┌─────────────────────────────────────┐
                    │  治理层 GOV-1..6（横切全部层次）      │
                    │  能力清单 · 分离哈希 · 创世窗口 · 三关 │
                    └──────────────────┬──────────────────┘
  ┌────────────────────────┐  ┌────────┴─────────┐  ┌────────────────────────┐
  │ 声明层（语义契约/TBox） │  │ 事实层（权威状态） │  │ 观测层（非权威）        │
  │ spec/ 九类 YAML         │→ │ 本体事件日志       │← │ 会话事件流              │
  │ ObjectType…ActionType  │  │ + 只读投影         │  │ Agent 看到/想了什么     │
  └────────────────────────┘  └──────────────────┘  └────────────────────────┘
       编译/校验/注册            追加经 Action            通道写入，独立存储
```

## 2. 五条公理及其工程含义

| 公理 | 原文要点 | 工程含义（落到本项目的何处） |
|---|---|---|
| **AX-1 事件即真源，行动即变更** | 状态是事件流的投影；改变状态唯一途径是经 ActionType 评估后追加事件；外部现实只作观测 | `kernel/store.py` 无 update/delete；`kernel/pipeline.py` 唯一提交入口；`kernel/session.py` 物理分离 |
| **AX-2 概率性提议，确定性断言** | 概率机制只能提议；对世界的变更由确定性 Action 在治理边界完成 | `aos draft` 的解析器是确定性的；LLM 起草是实例侧 hook，产出同 DSL 过同一闸门 |
| **AX-3 三分离** | 类型/实例、声明/实现、平台契约/上下文边界全程保持 | 声明在 `spec/`，实现在 `src/`，能力面由清单界定；Agent 无特权通道 |
| **AX-4 闭环可审计** | "基于什么信息、发起什么行动、结果如何"事后可重放 | 解释器审计（版本+快照哈希+结果）、决策双引用、append-only 日志（擦除降级 P-17 是范围注） |
| **AX-5 Schema 即数据** | 元 Schema 自身是四元组实例，可被治理、审计、Action 变更；治理是第一个工作流 | `capabilities.yaml` 三段式 + GOV-3 版本通道 + `aos spec version`；治理 Action 生效后重跑注册管线 |

**推导示例**：AX-1 → KS-1.1（日志唯一权威、append-only）→ KS-1.3（事务边界=单事件追加，不变量在追加前求值）→ KS-1.4（版本冲突完整重求值）→ INV-1（所有状态变更经 Action）→ VER-2/3（顺序与重求值实测）。这条链在 `pipeline.py` / `store.py` 的注释与守卫测试中逐环可查。

## 3. 三层数据 + 一层治理

### 3.1 声明层（Declarative / TBox 对应物）

**职责**：定义"允许什么"。九类声明是唯一语义真相源：

| 声明类 | 目录 | 承载的语义 | 对应模式/条款 |
|---|---|---|---|
| Object | `spec/ontology/objects/` | 对象类型、标识、属性及决策相关性 | T01、INV-8 |
| Link | `spec/ontology/links/` | 结构性链接（零属性/遍历透明/系统写入） | T09、P-4、VER-21 |
| Action | `spec/ontology/actions/` | 状态变更契约：参数、SC、权限、副作用（effects，T24 执行点）、审计 | T24、P-1、KS-7 |
| Context | `spec/contexts/` | 通用语言、steward、投影延迟预算 | P-3、P-16、VER-12 |
| Aggregate | `spec/aggregates/` | 聚合根、流、求值预算、不变量归属 | P-2、R8 |
| Invariant | `spec/invariants/` | 不变量三元组：声明 + 违规语义 + 修复绑定 | T10、P-6、INV-3 |
| Mapping | `spec/mappings/` | 跨上下文字段映射 + 语义损耗声明 + golden | P-5、KS-4、VER-14 |
| Process | `spec/processes/` | 跨聚合步骤与幂等补偿 | P-9 |
| Governance | `spec/governance/` | 职责授权矩阵（duty matrix）——治理面横切：岗位 × 动作 × 条件 | GOV-1、P-10 |

九类文件全部被 `registration.load()` 装载；任何一类缺失或非法，注册即失败。

### 3.2 事实层（Authoritative / ABox 对应物）

**职责**：记录"发生了什么"。核心是 `EventStore`——append-only、无 update/delete 路径（KS-1.1 / INV-1 / VER-28）。

- 每条事件携带九个字段（KS-1.2）：`event_id`、`stream_id`、`expected_version`、`event_type`（含 Schema 版本）、`payload`（含 valid time）、`transaction_time`、`action_id`、`principal` 等；
- 状态不是直接存储的，而是事件流的**只读投影**（T17 / P-16），删除物化后可全量重放重建（VER-26）；
- 决策事件单列**决策流**，经内置 `RecordDecision` 追加，不经域不变量门控（KS-2.6 / VER-33）。

### 3.3 观测层（Non-authoritative）

**职责**：记录"Agent 当时看到了什么、想了什么"。`SessionChannel` 与 `EventStore` **无任何共享结构**——物理分离，不构成本体状态，不参与权威重建（KS-2.2 / VER-4）；追加为内核中介的通道写入，逐条强制主体归属（KS-2.3 / VER-5）。

决策事件必须同时引用两侧的半边：**（投影标识, transaction_time）是权威事实，（会话事件引用）是推理证据**，两者永不互替（KS-2.5）。这是"有据可依"的机械形态。

### 3.4 治理层（横切）

| 机制 | 条款 | 落点 |
|---|---|---|
| 两级社会契约：算术（平台强制）+ 正当性（社会担保） | GOV-1 | `bootstrap --stage 1` 强制外部任命凭据；模板不合成 |
| 工件同一性与内容寻址 | GOV-2 / 2.3 / 2.4 / 2.5 | 分离式哈希 `tools/hash_spec.py`、指纹 `tools/fingerprint.py`、登记表 append-only |
| SpecChange 提案通道 | GOV-3 | `aos spec version <v> --proposal-ref`；冻结文本不就地改 |
| 新模式准入 | GOV-4 | 提案须引用所预防的事故类别（附录 B.2 A–R），生效重跑失败即阻断 |
| 冻结复审与自曝 | GOV-6 | 处置记录区分前提订正 / 设计级接受-修正-反对 / 自曝 |

## 4. 模式为何存在：以事故反证

17 个模式（P-1..P-17）每条都带一个"**移除后果**"字母，指向附录 B.2 的事故类别。这不是装饰：GOV-4 规定新提案必须引用它预防的已识别事故类别。也就是说，**模式的合法性来自它防止的事故，不来自设计品味**。

| 模式 | 主题 | 移除后果 | 事故形态（摘要） |
|---|---|---|---|
| P-1 | 声明式 Action | A | 行为真相双源：Action 外代码改状态，审计断裂 |
| P-2 | Aggregate 一致性边界 | B | 不变量越界求值、并发冲突未锁定 |
| P-3 | Bounded Context | C | 本体政治学全局化，裁决无据 |
| P-4 | 结构性链接 | D | 约束模式漂移成约定、跨上下文能力泄露 |
| P-5 | 声明式 Mapping | E | Mapping 静默腐烂，审计只见过滤后世界 |
| P-6 | 不变量三元组 | F | 传感器无响应协议：违规路由到虚空 |
| P-7 | 违规即对象 | G | 违规降级为日志，聚合视图需查询重建 |
| P-8 | Identity Context | H | 概率匹配直接归并、归并史不可重放 |
| P-9 | ProcessType 跨聚合 | I | 流程编码于应用服务，分布式事务硬凑原子性 |
| P-10 | Agent 居住地 | J | Agent 全局权限，围堵失效 |
| P-11 | Schema 即数据 | K | 治理规则存于配置/PR，Schema 变更脱离治理 |
| P-12 | Dry-Run | L | 批准基于过期信息，部分覆盖当作全覆盖 |
| P-13 | 双时态记录 | M | 单时态伪装双时态，审计不可重放 |
| P-14 | 存量合规 | N | 存量无迁移路径，新不变量上线即停摆 |
| P-15 | 基座与破窗 | O | 基座被稀释或膨胀 |
| P-16 | 投影与决策输入 | P | 决策依据无锚点，"当时看到什么"不可回答 |
| P-17 | 可验证遗忘 | Q | 遗忘权与审计只增冲突未解 |

事故 **R（介质分歧）**不由某个 P 承载：v2.0 以"正文零表格承载 MUST + 指纹清单 + 双编码条款"对其**结构性灭绝**（附录 B.2 / GOV-2.4）。本项目曾实测到布线 YAML 改键序后正则静默丢项（27→26），正是 R 类事故的现实例证；修订是把 `verification.yaml` 统一到 `tools/wiring.py` 单一 pyyaml 读取点。

## 5. 事件流拓扑：四条流、两个世界

```
  外部观测 ──摄取 Action（带出处）──┐
                                   ↓
  ┌────────────────────── 本体事件日志（权威） ──────────────────────┐
  │  域聚合流 domain:ContractAggregate   ← 域不变量门控              │
  │  决策流   domain:decision             ← 仅 SC 结构校验 + 主体归属  │
  │  identity 流 domain:identity          ← DeclareIdentityMerge 单写者│
  │  invariant 流 domain:invariant        ← RaiseInvariantViolation   │
  └──────────────────────────┬───────────────────────────────────────┘
                             │ 只读投影（可重建）
                             ↓
                       Agent 决策输入 ←──双引用── 会话事件流（非权威、物理分离）
```

四条流的隔离不是命名约定：

- 决策事件 MUST NOT 经域聚合不变量门控（KS-2.6）——否则"记录一个决定"会被业务规则 blocking；
- 违规对象 MUST 经 `RaiseInvariantViolation` 写入（INV-10），探测器只求值、不直写；
- 归并声明 MUST 经 `DeclareIdentityMerge` 写入且双向记录（P-8 / INV-13）；
- 会话内容对不变量与 SC 的求值闭包不可达（KS-2.4）。

## 6. 时间、演化与创世窗口

| 主题 | 条款 | 模型 |
|---|---|---|
| 双时态 | KS-6 / P-13 | `valid_time ∈ (−∞, transaction_time]`；禁止未来有效时间；补录带出处并触发投影重建标记，但不重跑历史门控判定 |
| Schema 演化 | KS-5 / INV-9 | 事件负载带 Schema 版本；旧事件永久保留；读时 upcasting 为纯映射，**无注册路径即读失败**；golden 锚定历史快照 |
| 创世窗口 | KS-8 / T20–T22 | `open → frozen`（TTL 到期未闭环，可再授权）或 `open → extinguished`（治理周期闭环，**不可逆**）；创制任命记为审计第一条 |
| 可验证遗忘 | P-17 | 密钥销毁后，重放降级为哈希承诺验证；审计只增与"销毁事件结构本身"不可调和（§9.2 明示不适用） |

## 7. 受限解释器与审计：规则如何"可执行"

KS-3.2 的 R1–R11 是规则执行的安全边界，**按调用树整体适用**：

| 类别 | 规则 |
|---|---|
| 允许 | R1 聚合内属性读取；R2 显式枚举的快照输入（每次求值捕获一次）；R3 纯集合操作 |
| 禁止 | R4 任何 I/O；R5 系统时钟（"现在"只能来自求值上下文）；R6 无界递归/循环；R7 修改聚合状态；R9 命名空间混用；dunder 属性链（`__class__` / `__base__` 等，R1 输入封闭的实现释义：属性读取仅指声明字段，类型结构自省不是属性读取） |
| 预算 | R8 集合规模上限由 AggregateType 声明，缺省 10⁵；注册期超限拒绝，运行时门控超限 fail-closed，探测器路径超限产生违规对象——**禁止静默降级** |
| 两档 | R10 布尔档结果只能是 true/false；R11 映射档允许数据整形与**结构分派**（版本、字段存在性、空值、字面量等值），禁止**判断分派**（语义谓词） |
| 审计 | KS-3.3：解释器版本 MUST 进求值审计并出现在能力清单上；实现留档为（版本, 快照哈希, 结果） |

纯度封闭律（KS-3.1）：受限域对宿主域封闭；宿主函数禁止进入重放路径；布尔档可调用映射档，映射档不得调用布尔档。`mapping_profile.py` 在**结构上没有谓词分派入口**，因此"判断不嵌入变换内部"不是靠约定，而是靠不可表达。

> 诚实边界：解释器纯性无法被证明，只能被实现与核对。模板交付的是 AST 白名单（含 dunder 属性拦截）、空 `__builtins__`、深度上限与审计记录，不宣称"已证明纯"。

## 8. 三关核对与发布闸门

`aos verify` 三关串联，任一失败即 exit 1：

1. **结构层**（GOV-2.4）：条款条数 + 首锚 + 末锚，由 `tools/fingerprint.py` 核对；失败按 GOV-2.5 二分"正典缺内容 / 副本退化"。
2. **密码学层**（GOV-2.3）：`tools/hash_spec.py` 对 `docs/aos-spec.md` + `docs/SPEC-FINGERPRINT.md` 按声明顺序做 sha256；漂移即冻结文本被改，拒绝并指向 GOV-3。
3. **注册层**（KS-7.2 第 5 步）：`declared == registered`——编译产物与 `config/capabilities.yaml` 生成段逐条比对，不一致即失败。

`aos release` 在这三关之上再加两关：布线套件全绿（`tools/wiring.py` 单一解析点，缺路径阻断）+ 骨架字节级零漂移（`tools/codegen.py`）。全绿才写 `dist/RELEASE-MANIFEST.json`；任一失败不出制品（fail-closed / VER-27 前置）。

> 结构层是**弱在场证明**——它不校验中间条款内容；强保证来自密码学层的全文哈希。这是附录 F 清单定义的取舍，不要误读为"指纹通过 = 规范未改"。

## 9. 适用边界（采用前必须读）

规范 §9 给出的边界，原文口径不可软化：

- **适用**：错误代价远大于建模成本的领域（金融敞口、临床试验、合约审批、国防决策、关键基础设施）；
- **显式不适用**（采用前 MUST 声明）：① 合规要求销毁事件结构本身而非仅销毁可读性；② 决策者拒绝建模投资、要求开箱即用；③ 无法指定 steward 的领域；
- **不可声明化残余（仅三项）**：内核能力集裁定（BOOT-0，系统外行为）、创制任命（BOOT-1，审计第一条）、经 KS-4.1 路径二的观测其历史重建依赖外部系统自身可审计性——AOS 只保证本体半边的重放。

模板层对应的诚实边界：`bootstrap --stage 2/3` 返回拒绝（治理工作流与 Identity Context 验收属实例侧世界事件）；〔强〕项只有 checklist/support，不伪装成通过。

## 10. 小结与下一站

- 体系逻辑是**公理派生 + 不变量裁决 + 验证矩阵强制**，不是松散的最佳实践合集；
- 架构是**三层数据 + 治理横切**，四条流物理/逻辑隔离，投影是唯一读路径；
- 模式以**事故反证**，提案以事故引用准入，验证以条款号布线。
