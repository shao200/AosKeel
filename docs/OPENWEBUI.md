## 启动

镜像默认 pin 到 `v0.13.4`（可用 `AOS_OPENWEBUI_IMAGE` 覆盖），端口仅绑定 `127.0.0.1:3000`。注册默认关闭，首次启动须预置管理员：

```bash
mkdir -p spec/drafts
WEBUI_ADMIN_EMAIL=admin@example.com WEBUI_ADMIN_PASSWORD='<强密码>' \
  docker compose -f docker-compose.openwebui.yml up -d
```

模型后端需自备 Ollama 或 OpenAI-compatible API（用 `OLLAMA_BASE_URL` / `OPENAI_API_KEY` 环境变量指向）。正式部署前置 SSO/认证网关；不要开放注册或直接暴露公网。

## 导入 Pipe

在 Open WebUI 中以管理员身份导入 `src/generated/openwebui_pipe.py`，模型选择器中出现 `AosKeel Console`。设置 Valves：

- `INSTANCE_ROOT` = `/aos-instance`（容器内挂载点）；
- `ROLE_MAP_JSON` = 由管理员维护的目录身份 → AOS 角色映射，例如 `{"admin": ["contract_steward"], "default": []}`。

输入 `/help` 查看能力，`/nav` 查看按角色过滤的可见动作，`/cmd review`、`/draft requirements.txt --name r1` 分别走只读查询与草稿通道。

## 不可越过的边界

- Pipe 不 import 内核、不调用 `Kernel.submit()`；只经 subprocess 调实例 CLI。
- `spec version` / `spec register-declarations` / `draft promote` / `register` / `bootstrap` / `release` 一律不可用，必须走终端。
- `review` / `manual` 的 `--out` 与 `extract` 的 `--extractor` 在 Pipe 内禁用：前者可写盘，后者可执行实例内脚本。
- 草稿名只允许 `[A-Za-z0-9_-]{1,64}`，防止 `draft-{name}.yaml` 拼出 `spec/drafts/`。

- 实例根以只读挂入容器，仅 `spec/drafts/` 可写；只读白名单不含任何写选项。
