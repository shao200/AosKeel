# AOS 生产存储与真实性蓝图（实例侧，非模板实现）

> **定位**：本文是"把模板推到生产"的协议与验收清单，**不是模板承诺**。
> 模板只交付门禁、事件流语义、Process 构造与单写进程参考实现；多进程存储、
> 密钥托管、轮转与演练属实例侧职责。凡本文要求的保证，模板均**未实现**，
> 也不应被 README 的 fail-closed 表述暗示为已实现。

## 1. 目标与非目标

目标：在不改变内核写路径语义的前提下，让 `EventStore` 协议在生产存储上成立：
streams 只读、`commit` 唯一写面、审计只增、版本冲突可重试、观察链不参与权威重建。

非目标：分布式事务、跨区域强一致、把通知/工作项升格为业务事实、由 LLM 决定授权。

## 2. 存储适配协议（必须逐条成立）

| 约束 | 生产实现要求 | 验收方式 |
|---|---|---|
| streams 只读 | 外部只经查询快照读取；无 UPDATE/DELETE 接口 | 权限审计 + 代码检索 |
| `commit` 唯一写面 | 所有写入带 `expected_version`，事务内比较并追加 | 并发冲突测试 |
| 审计只增 | `appended` / `structurally-rejected` 同事务落库 | 故障注入：拒绝也留痕 |
| 八字段事件 | 缺字段即拒；不接受"补默认值" | 反序列化负向测试 |
| valid_time | 存储层再校验时区/可解析性，拒绝不得落行 | 半写入测试 |
| 幂等重试 | 业务幂等键 + `(stream, expected_version)` 双约束 | 重复提交测试 |

适配器只能实现协议，**不得**在门禁之外补写、修正或"修复"业务状态。

## 3. 崩溃一致性

- 一次提交 = 一个事务：事件行、审计行、版本推进要么全成，要么全不成。
- 拒绝路径必须先于写入判定；拒绝后事件表零变化。
- 重放只修复**文件/段尾**未完成记录（对应模板 `kernel/jsonl.py` 的尾部修复），
  中段损坏一律拒绝加载并告警，不做"跳过坏行继续跑"。
- 每段建议带段内校验和；校验失败按中段损坏处理。

## 4. 单写与 fencing

模板的进程锁只覆盖单机单进程。生产多实例必须引入**租约 + epoch**：

1. 写入者先取得租约（带 TTL 与 epoch），提交时携带 epoch；
2. 存储核对 epoch 是否仍为当前值，过期写入一律拒绝（fencing token）；
3. 旧持有者恢复后不得凭本地缓存继续写，必须重新读水位并重新求值；
4. 观察链（会话/选择/锚定）与权威流分库/分表，并各自遵守同一租约规则。

只有锁、没有 epoch，等于给"暂停的写者"留了复活窗口。

## 5. 快照 + 尾段（不允许截断审计）

- 快照记录 `(stream, watermark_version, reducer_digest)`；`reducer_digest` 防止
  用错版本的归约器重建。
- 读取 = 快照 + watermark 之后的尾段事件；快照缺失即回退全量重放，不静默空读。
- 压缩只允许删除**已被快照覆盖且不再被引用**的事件，审计与决策引用永不删除。
- 重建必须可重复：同一 watermark 的两次重建结果逐字段相等。

## 6. Outbox 与观察投递

- 需要"业务事实落地后必然派发"时，用同事务 outbox，而不是裸双写；
- 投递幂等键建议 `(source_event_id, action, position)`；
- 送达失败重试、投递状态、通知记录属于观察层：可重建、可丢弃，不进权威流；
- "到期未办"由"应有业务事件缺席 + SLA"读时派生，不新增 `expired` 事件。

## 7. 保留、轮转与恢复

- 段文件只追加；轮转后旧段进入只读层并保留校验和清单；
- 备份必须可独立验签/验和；恢复演练至少覆盖：空库、尾段半行、中段损坏、快照缺失；
- 恢复后先跑重放一致性核对，再开放写入。

## 8. 真实性与密钥

- 哈希（如 `sha256:` 正典摘要）只证明**完整性**，不证明发布者身份；
- 需要真实性时，对发布清单做 Ed25519 分离签名（模板提供可选实现
  `tools/manifest_sign.py`，密钥由实例侧托管）；
- 私钥不得进仓库、不得进 CI 明文变量；建议 KMS/HSM 或签名服务；
- 密钥轮转需保留旧公钥用于历史验签；清单中的 `key_id` 只作索引，不是信任根；
- 阈值签名/双人签署属合规增强，不在模板范围。

## 9. 可观测与演练

最低度量：提交拒绝率（按 kind）、版本冲突重试率、重放耗时、段校验失败数、
投递积压、租约切换次数。每季度至少一次：断电式崩溃恢复演练、篡改检测演练、
密钥轮转演练，并保留证据引用（谁、何时、依据）。

## 10. 迁移与兼容

- 事件 schema 变更只走上行转换（upcasting），不原地改历史；
- 新旧存储双跑用 shadow 对账，差异必须可解释；
- 切换前冻结写入、核对水位、切换租约 epoch，再解冻；
- 回滚方案必须包含"旧存储仍可读、事件不丢失"的证明。

## 11. 验收清单（缺一不可）

| 项 | 证据 |
|---|---|
| 并发提交无重复/无空洞 | 冲突注入测试报告 |
| 拒绝不落盘 | 事件表 diff 为空 |
| 崩溃尾段可恢复 | 恢复演练记录 |
| 中段损坏拒绝加载 | 告警与拒绝日志 |
| 快照重建可重复 | 两次重建逐字段相等 |
| 观察链可丢弃重建 | 删除观察库后业务读取不受影响 |
| 发布真实性 | 签名清单 + 独立验签记录 |
| 密钥不落库 | 仓库与 CI 扫描报告 |

## 12. 诚实边界

模板当前提供的是：协议语义、单写进程锁、尾部半行修复、拒绝审计与哈希完整性。
本文其余内容均为**实例侧工程**；在完成第 11 节证据之前，不应对外声称"生产就绪"，
也不应把 fail-closed 测试等同于合规认证或真实签名。
